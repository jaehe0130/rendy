# 와이어프레임 확인 필요 사항

Figma 와이어프레임을 읽으면서 개발 전에 정해야 할 것들을 모았습니다. 디자인 담당이 정리 후 체크해 주세요.

## 개발에 바로 영향

- [x] **서비스명 통일** — **Rendy (렌디)**로 확정 (2026-11-06). 피그마 와이어프레임의 "모두의 물건"(상단 타이틀, 0-1 결론 카드, 0-3 공유 카드)을 렌디로 바꾸기 → 디자인 담당
- [ ] **2-5 결제 완료 화면 없음** — 3-3, FLOW 4 진입점, 4-4 설명에서 "2-5"를 참조하지만 프레임이 없음.
- [ ] **4-4 설명 수정** — "받을 때 사진(2-5에서 기록)"이라고 되어 있는데, 실제 기준 사진은 8-1(운영자 출고 6면)과 8-2(고객 받은 날 3장).
- [ ] **4-5와 8-3·8-4 중복** — 같은 AI 파손 판정 화면이 두 벌. 8-x로 통일하고 4-5는 삭제(화면 맵에 '삭제'로 표시해 둠).
- [ ] **운영자 화면 헤더** — 8-1, 8-5는 운영자 화면인데 고객용 `Wire/GNB`를 씀. 6-x, 7-6처럼 `Wire/AdminHeader`로 (라우트도 `/admin`).
- [ ] **2-4 / 3-3 / 7-5 주문 화면 3개가 거의 같음** — 하나의 `/checkout` 컴포넌트(꾸러미·쿠폰은 상태)로 구현 예정.
- [ ] **6-4 번호 비어 있음** — 6-3 다음이 6-5. 빠진 화면인지 번호만 건너뛴 건지 확인.

## AI 흠집 비교에 영향 (중요)

- [ ] **촬영 면이 서로 다름** — 운영자 출고(8-1)는 정면·왼쪽·오른쪽·뒷면·윗면·작동 6장, 고객(8-2, 4-4)은 정면·옆면·작동 3장. AI는 *같은 면끼리* 비교하므로 고객의 "옆면"이 왼쪽인지 오른쪽인지 정해야 함.
- [ ] **윗면 파손을 고객 사진으로는 못 잡음** — 8-4 예시가 "윗면 모서리 깨짐 4.2cm"인데 고객 반납 3장에 윗면이 없음. 고객 촬영에 윗면 추가 또는 "회수 후 운영자 6면 재촬영"을 8-5 앞에 추가.
- [ ] **2cm 기준 근처 표시** — 실험상 길이 오차가 평균 1.5cm라 8-3 예시(1.6cm)처럼 기준 근처는 자동 분류를 믿기 어려움. `damage-policy.json`의 `reviewMarginMm` 안이면 고객 화면에 "운영자 확인 후 확정" 상태로 보여주기.

## 발표에 영향

- [ ] **8-5 'AI 성능' 예시 수치** — "길이 오차 ±0.4cm, 일치율 91%"가 실제 실험(길이 오차 평균 약 1.5cm)보다 훨씬 좋게 보임. 화면에 "예시"라고 적혀 있지만 심사위원은 숫자를 기억함. 실험값으로 바꾸거나 "목표"라고 명확히 표기 → `docs/ai/experiments.md` 참고.
